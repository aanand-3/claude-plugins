# P-087: Read-only agents MCP tool

## Context
CHORE-002 (G-003): `crew.mjs agents --check` exists only on the CLI, so an agent that wants to know whether the role
definitions in `.claude/agents/` are missing or stale has to shell out. The MCP `doctor` tool already reports this as
one of its checks (`views/doctor.ts`, `agents` check, WARN per problem), so most of the need is covered. What is left
is a small, read-only MCP tool that answers just this question with the same result as `agents --check`. Rendering
stays CLI-only and human-only on purpose: the guard denies `crew.mjs agents` without `--check` as a write to
`paths.protected` (`commands/team/guard.ts`), and no MCP tool may write agent definitions.

## Scope
**In:**
- A read-only MCP tool `agents` registered in `commands/team/agents.reg.ts`, which runs the existing check path
  (`agents(store, true)`): it lists `STALE <path>: <problem>` per missing, stale or orphaned definition, or
  `Agents up to date.`; the result is an error result when any problem is found (exit code 1), like `doctor`.
- The generated MCP-tools rows in `plugins/crew/docs/reference.md` (regenerated by `npm run docs`).
- Test updates: the exact tool list in `test/mcp.test.ts`, and an e2e case in `test/hub/e2e/agents.test.ts`.

**Out (explicitly not doing):**
- Any MCP tool or option that renders, writes or removes agent definitions.
- Changing `agents` CLI behaviour, its help line, `doctor`, or the guard.
- A `--json` output for `agents --check`.

## Acceptance criteria
- [ ] AC1: `tools/list` includes a tool named `agents` whose description says it is read-only (same check as
  `crew.mjs agents --check`, never renders) and whose input schema takes no arguments beyond the common ones `obj()`
  gives every tool.
- [ ] AC2: In a project whose agents are rendered and current, calling the `agents` tool returns
  `isError: false` and text containing `Agents up to date.`, matching `crew.mjs agents --check` output.
- [ ] AC3: After deleting one rendered agent file and editing another, the `agents` tool returns `isError: true`
  with one `STALE` line naming each (`missing`, `stale against the policy or its template`), matching
  `crew.mjs agents --check`; and `.claude/agents/` is byte-identical before and after the call (the tool writes nothing).
- [ ] AC4: The `agents` CLI command, its help line and the frozen registry checks are unchanged:
  `test/hub/registry.test.ts` passes without edits and `git diff --quiet main -- packages/crew/test/hub/registry-before.json`.
- [ ] AC5: `plugins/crew/docs/reference.md` lists `agents` with its MCP tool (no longer "CLI only") and
  `test/docs.test.ts` passes after `npm run docs`.

## Approach
- In `agents.reg.ts` add `tools: { agents: { description, input: obj(), run: (st) => agents(st, true) } }`, importing
  `obj` from `../../registry.js` as `doctor.reg.ts` does. `runTool` in `mcp.ts` already maps a non-zero return to
  `isError` and captures `store.say` output, so no change to `agents.ts` or `mcp.ts` is needed.
- Description (suggested): "Whether the role agents in .claude/agents/ are rendered and current (`crew.mjs agents
  --check`): one STALE line per missing, stale or orphaned definition; an error result means some are. Read-only:
  only the human renders agents (`crew.mjs agents`)."
- The tool name mirrors the CLI command, per the registry convention (K-2026-10-25 each command registers its CLI spec
  and MCP tool in its .reg.ts). Generated build outputs (dist, references/commands.md) are left to Release
  (K-2026-10-24); the e2e test runs the bundle, so the developer runs `npm run build` locally to exercise it but does
  not need to keep dist changes.
